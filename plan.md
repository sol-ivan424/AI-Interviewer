## 1. Назначение документа

Этот файл — единый источник порядка разработки вместе с `PRD.md`.

Правила для агентов:

- Не удалять файлы, данные или функциональность без однозначного разрешения пользователя.
- Не реализовывать функции из раздела Out of Scope.
- Не смешивать HTTP, бизнес-логику и работу с БД.
- Не переходить к следующему этапу, пока текущий не работает и не проверен.
- Задача считается завершённой только после реализации, тестов и обновления документации.
- После каждого этапа обновлять чекбоксы и журнал решений в `plan.md`.
- При расхождении документов приоритет имеет `PRD.md`, затем инструкции пользователя.

Обозначения:

- `[ ]` — не начато.

- `[!]` — заблокировано, причина записана в журнале.

## 2. Зафиксированные решения

- Монорепозиторий: `frontend`, `services/api-service`, `services/llm-service`, позднее `services/ml-service`.
- Backend: FastAPI, Pydantic, async SQLAlchemy, Alembic, PostgreSQL, pytest.
- Frontend: Next.js App Router, TypeScript, Tailwind CSS, React Hook Form, `fetch`.
- Auth: JWT access token без refresh token; frontend передаёт его через `Authorization: Bearer`.
- Пароли хешируются современным password hasher и никогда не логируются.
- Основной scoring после Phase 2 — локальная LLM; rule-based scoring всегда остаётся fallback.
- API-service взаимодействует с Ollama только через llm-service.
- Интервью содержит пять зафиксированных вопросов; повторное открытие не меняет их порядок.
- Общий процент считается относительно максимума всех назначенных вопросов. При ручном завершении неотвеченные вопросы дают ноль.
- Для чужого интервью API возвращает 404.
- Redis запускается в инфраструктуре, но кеширование не добавляется до появления обоснованного сценария.
- ML-service не входит в первый релиз и добавляется только после стабильной LLM-версии.
- Модель Ollama загружается отдельной документированной командой, а не автоматически при сборке.
- Начиная с Phase 9 интервью содержит 3 зафиксированных seed-вопроса и до 2
  сохранённых адаптивных вопросов; общее число по умолчанию остаётся равным 5.
- Начиная с Phase 9 LLM вызывается через внешний OpenAI-compatible API внутри
  `llm-service`; старый Ollama-контур сохраняется как история MVP.
- Граф знаний хранится реляционно в PostgreSQL; отдельная graph database не нужна.

## 3. Целевая архитектура

```text
Next.js frontend
       |
       v
FastAPI api-service ---- PostgreSQL
       |                 Redis
       v
FastAPI llm-service
       |
       v
Ollama

Позднее:
api-service -> ml-service -> сохранённые ML-модели
```

Слои API-service:

```text
routers      — HTTP, статусы и сериализация
services     — бизнес-правила и транзакционные сценарии
repositories — запросы к БД
schemas      — входные и выходные контракты
models       — SQLAlchemy-модели
core         — конфигурация, безопасность и ошибки
```

## 5. Публичные интерфейсы

Обязательные API-service endpoints:

```text
POST /api/v1/auth/register
POST /api/v1/auth/login
GET  /api/v1/users/me
GET  /api/v1/roles
POST /api/v1/interviews
GET  /api/v1/interviews
GET  /api/v1/interviews/{id}
POST /api/v1/interviews/{id}/answers
POST /api/v1/interviews/{id}/finish
GET  /api/v1/interviews/{id}/result
GET  /api/v1/analytics/summary
GET  /api/v1/analytics/skills
GET  /api/v1/analytics/progress
```

Дополнение к контракту PRD: получение интервью включает историю уже отправленных ответов для восстановления UI после перезагрузки.

Ошибки:

- 401 — токен отсутствует или невалиден.
- 404 — интервью не существует либо принадлежит другому пользователю.
- 409 — конфликт состояния или повторный ответ.
- 422 — ошибка входных данных либо недостаточный пул вопросов.
- 502/503 внутри llm-service — контролируемая ошибка runtime; API-service применяет fallback.

## 6. Обязательные сценарии тестирования

- Регистрация, duplicate email, вход, ошибочный пароль, `/users/me`.
- Создание интервью с ровно пятью зафиксированными вопросами.
- Повторное открытие с тем же порядком и восстановленной историей.
- Полный, частичный, неверный и пустой ответ.
- Последовательная, повторная и конкурентная отправка.
- Автоматическое и ручное завершение.
- Запрет ответа после завершения.
- Запрет доступа к чужому интервью.
- Корректный результат по каждой теме.
- Пороговые значения рекомендаций: 39%, 40%, 69%, 70%.
- Пустая и заполненная аналитика.
- Сортировка progress по `finished_at ASC`.
- Доступная LLM, timeout, network error, пустой и невалидный JSON.
- Полный пользовательский путь в браузере.
- Запуск проекта с чистыми Docker volumes по README.
